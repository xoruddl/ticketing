# 기능 명세

이 프로젝트가 만들 기능의 범위다. **무엇을** 만드는지만 적고 **어떻게** 만드는지는 적지 않는다.
구현 방식은 `ai_docs/PROBLEMS.md`의 각 Step에서 문제를 겪으며 정한다.

**범위 기준**: 동시성이나 모듈 경계에 **새 문제를 만드는 기능**만 넣는다.
현실적이어도 새로 배울 문제가 없는 기능은 뺀다 (맨 아래 "범위 밖").

---

## 도메인

| 개념 | 설명 |
|---|---|
| 공연 (Performance) | 제목, 공연장 |
| 회차 (Schedule) | 공연의 날짜·시간별 편성. 시작 시각이 있다 |
| 좌석 (Seat) | 공연장의 구역·열·번호, 등급, 가격. **같은 좌석이 회차마다 따로 팔린다** |
| 예약 (Reservation) | 사용자가 회차의 좌석을 잡은 것 |
| 결제 (Payment) | 예약에 대한 결제 |
| 티켓 (Ticket) | 확정된 예약에 발급되는 입장권 |

### 사용자에게 보이는 예약 상태

```
선점 ──결제 성공──▶ 확정 ──취소──▶ 취소됨
  │
  └──유효 시간 초과──▶ 만료
```

## 기능

### F1. 좌석 조회

- 회차의 좌석 목록과 각 좌석의 예매 가능 여부를 조회한다
- 공연·회차·좌석 **등록 기능은 만들지 않는다.** 테스트 데이터와 초기 데이터로 넣는다

### F2. 좌석 선점

- 사용자가 회차의 좌석 **하나**를 선점한다
- 선점되었거나 확정된 좌석은 다른 사용자가 선점할 수 없다
- 동시에 여러 요청이 와도 한 좌석의 선점은 하나뿐이다
- 선점에는 유효 시간이 있다 (값은 설정으로 둔다)

### F3. 선점 만료

- 유효 시간 안에 결제되지 않은 선점은 만료되고, 좌석은 다시 예매 가능해진다
- 만료된 선점으로는 결제할 수 없다
- 만료와 결제가 동시에 일어나도 둘 중 하나만 반영된다

### F4. 결제와 예약 확정

- 선점한 사용자만 그 선점에 결제할 수 있다
- 결제에 성공하면 예약이 확정된다
- 결제에 실패했을 때 선점이 어떻게 되는지 정해져 있다
- 같은 결제 요청이 다시 와도 결제는 한 번만 된다
- 결제는 외부 PG를 통한다. 결과를 모르는 경우(타임아웃)를 다룬다

### F5. 발권

- 예약이 확정되면 티켓이 발급된다
- 티켓을 조회할 수 있다

### F6. 예매 조회

- 예약 단건을 조회한다 (상태, 회차, 좌석, 결제, 티켓)
- 내 예매 목록을 조회한다

### F7. 취소와 환불

- 확정된 예약을 취소할 수 있다. 회차 시작 전 정해진 기한까지만 가능하다
- 취소하면 PG에 환불을 요청하고, 티켓을 무효화하고, 좌석을 다시 판다
- 같은 예약에 취소가 여러 번 와도 환불은 한 번만 된다
- 환불이 실패하거나 결과를 모를 때 예약이 어떤 상태로 끝나는지 정해져 있다

### F8. 알림

- 예매 확정·취소 시 사용자에게 이메일을 보낸다
- 실제 발송 대신 가짜 발송기로 충분하다

### F9. 사용자

- 사용자 프로필(이메일 등)을 조회만 한다
- 회원가입·로그인은 만들지 않는다. 인증은 `app` 필터가 `UserId`만 넘기는 수준이다

### F10. 대기열 (선택)

- 인기 회차 오픈 때 입장 순서를 제어한다
- **측정 결과로 필요가 보일 때만** 넣는다

## Step별로 등장하는 기능

| Step | 기능 |
|---|---|
| 0 | F1, F2, F4(내부 가짜 결제), F5, F6 — 만료 시각이 지나면 결제 거절(F3 일부) |
| 1–2 | F2의 동시성 |
| 3 | F3 |
| 4–6 | F5가 `ticket` 모듈이 된다 |
| 7–8 | F4의 외부 PG, 결과 모름, 멱등성 |
| 9 | F7 |
| 10 | F2·F3의 인스턴스 2개 |
| 11 | F10 (선택) |
| 13 | F8, F9 |

## 범위 밖

| 기능 | 빼는 이유 |
|---|---|
| 관리자 (공연·회차·좌석 등록, 오픈) | CRUD라 새 문제가 없다 |
| 정산·매출 | 동시성·경계와 무관하다 |
| 매크로 방지, 1인 구매 매수 제한 | 보안·정책 문제다 |
| 입장 처리 (티켓 사용) | 발권 이후라 흐름에 새 경합이 없다 |
| 회원가입·로그인 | 인증은 모듈이 아니다 (`AGENTS.md`) |
| 할인·쿠폰·등급별 가격 정책 | 계산 규칙일 뿐이다 |
| 한 사용자가 여러 좌석을 한 번에 선점 | **후보.** 락 순서와 데드락 문제를 다루고 싶어지면 넣는다 |
