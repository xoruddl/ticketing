# CLEAN CODE

코드를 쓰거나 고칠 때 지키는 규칙이다. **리뷰 전에 스스로 훑고, 어긴 항목이 있으면 왜 어겼는지 한 줄을 남긴다.**

- 포맷(들여쓰기·줄 길이)은 사람이 지키지 않는다 — Spotless가 강제한다 (`ai_docs/CONTRIBUTING.md`)
- 모듈 경계 규칙은 `AGENTS.md`에 있다. 이 문서는 **모듈 안쪽의 코드**를 다룬다

## 클린코드 체크리스트

우아한테크코스 객체지향 생활 체조 원칙을 기준으로 한다.

| # | 규칙 | 기준 |
|---|---|---|
| 1 | 메서드 들여쓰기는 한 단계만 | `for` 안의 `if`가 되면 안쪽을 메서드로 뽑는다 |
| 2 | `else`를 쓰지 않는다 | 이른 반환(early return)으로 대신한다 |
| 3 | 원시값과 문자열을 포장한다 | `Long seatId` 대신 `SeatId`, `int amount` 대신 `Money`. 검증과 연산이 그 타입에 모인다 |
| 4 | 컬렉션은 일급 컬렉션으로 감싼다 | 컬렉션에 걸린 규칙(중복 금지, 개수 제한)이 그 클래스 안에 들어간다 |
| 5 | 한 줄에 점(`.`)은 하나 | 디미터의 법칙. `reservation.getSeat().getSchedule().getStartAt()`은 리팩터링할 자리다 |
| 6 | 인스턴스 변수는 3개 이하 | 넘으면 줄이려는 시도를 한다 |
| 7 | 도메인 객체에 getter/setter를 두지 않는다 | 값을 꺼내 밖에서 판단하지 말고 객체에게 시킨다 |
| 8 | 메서드 인자는 3개 이하 | 4개 이상은 허용하지 않는다. 3개도 가능하면 줄인다 |
| 9 | 메서드는 한 가지 일만 한다 | 이름에 "그리고"가 들어가면 둘이다 |
| 10 | 클래스를 작게 유지한다 | 한 문장으로 책임을 설명할 수 없으면 크다 |

### 이름

- 축약하지 않는다. `rsv`, `pmt` 대신 `reservation`, `payment`
- 도메인 용어는 `ai_docs/FEATURES.md`의 영문 이름을 그대로 쓴다 (Performance, Schedule, Seat, Reservation, Payment, Ticket)
- 불리언은 질문형으로: `isExpired()`, `canCancel()`
- 테스트 메서드명은 한글로 행동을 적는다: `이미_선점된_좌석은_선점할_수_없다()`

### 예외

- 실패를 `null`이나 `-1`로 돌려주지 않는다. 예외 또는 결과 타입으로 드러낸다
- 도메인 규칙 위반은 도메인 예외로 던진다. 메시지에 **무엇이 왜** 실패했는지 적는다
- 예외를 잡아서 삼키지 않는다. 잡았으면 처리하거나 감싸서 다시 던진다

## SOLID

| 원칙 | 뜻 | 이 프로젝트에서 보는 신호 |
|---|---|---|
| **S**RP 단일 책임 | 클래스가 바뀌는 이유는 하나 | 선점 정책이 바뀔 때와 결제 수단이 바뀔 때 같은 클래스를 고친다면 위반 |
| **O**CP 개방-폐쇄 | 확장에 열리고 수정에 닫힌다 | 새 경우를 추가할 때마다 기존 `if`/`switch`에 분기를 더한다면 의심 |
| **L**SP 리스코프 치환 | 하위 타입은 상위 타입을 대신할 수 있다 | 구현체가 `UnsupportedOperationException`을 던지거나, 테스트 더블이 실제와 다른 약속을 한다면 위반 |
| **I**SP 인터페이스 분리 | 쓰지 않는 메서드에 의존하지 않는다 | 조회만 필요한 쪽이 변경 메서드까지 있는 인터페이스를 받는다면 쪼갠다 |
| **D**IP 의존 역전 | 고수준 정책이 저수준 세부에 의존하지 않는다 | 도메인 코드가 HTTP 클라이언트·JPA·Spring 타입을 직접 import한다면 위반 |

- SOLID는 **판단 기준**이지 모든 곳에 인터페이스를 만들라는 뜻이 아니다. 구현이 하나뿐이고 바뀔 이유가 보이지 않으면 인터페이스를 만들지 않는다
- **모듈 간 통신에 DIP를 쓸지는 `PROBLEMS.md` Step 6에서 대안을 비교해 정한다.** 이 문서가 답을 미리 정하지 않는다
- 원칙을 이유로 구조를 바꿨다면, 무엇이 바뀔 이유였는지 커밋이나 `DECISIONS.md`에 남긴다

## 이 저장소에서의 예외

체크리스트는 도메인 객체를 겨냥한다. 프레임워크 코드에 그대로 대면 지킬 수 없는 항목만 **예외로 못 박고 나머지는 지킨다.**

| 항목 | 예외 대상 | 이유 |
|---|---|---|
| 인스턴스 변수 3개 | `@Service`·`@Component`의 생성자 주입 필드 | 협력자 수는 설계의 결과다. 대신 **주입이 4개 이상이면 책임을 쪼갤 신호로 본다** |
| getter/setter | JPA 엔티티의 getter, `record` DTO, 설정 프로퍼티 | 프레임워크가 접근자를 요구한다. 엔티티에 **setter는 여전히 두지 않는다** |
| 원시값 포장 | 요청·응답 DTO, DB 컬럼 매핑 | 직렬화 경계에서는 원시값을 쓴다. 포장은 경계 안쪽에서 한다 |

예외를 쓰더라도 **도메인 로직은 예외 밖이다.** 엔티티에 getter가 있는 것과, 선점 만료 판단을 엔티티 밖에서 하는 것은 다른 문제다.
